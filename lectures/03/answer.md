## 宿題

- 取り組んだレベル：実装
- やったこと：
  - 保存の前に利用者の承認を挟むツール `save_learning_log(title, content)` を作った
  - 実装の前に、Claude Code と要件を決めた。Pydantic AI が決めるのは「ツールを呼ぶか・承認されたか」までで、保存の形式や安全面は自分で決める必要があるため

    | 要件 | 決めた内容 |
    |---|---|
    | 粒度・形式 | 1回の保存で1ファイル。Markdown（`learning_log/YYYYMMDD-HHMMSS.md`） |
    | 保存先 | 固定。モデルにパスを決めさせない |
    | 上書き | しない（`open(..., "x")`） |
    | 承認画面 | title と content をすべて表示する。y 以外は拒否 |

  - `requires_approval=True` で登録し、`output_type=[str, DeferredToolRequests]` にした。承認待ちで止まったら利用者に y/N を聞き、その結果と `message_history` を渡して再開する
- 結果：

  | 操作 | 結果 | requests |
  |---|---|---|
  | y（承認） | ファイルが作られ、モデルが「保存しました」と回答 | 3 |
  | n（拒否） | ファイルは作られず、モデルが「保存されませんでした」と伝えて要点だけ回答 | 3 |

  - requests が演習の 2 から 3 に増えた。承認待ちで止まり、再開するときに LLM をもう1回呼ぶため
  - `uv run pytest -q`：16 passed

- 気づき・疑問：
  - 承認の仕組みはフレームワークにあるが、「何に承認を付けるか」「何を見せるか」は自分で決める要件だった。先に要件を決めたことで、迷わず実装できた
  - 承認画面に本文まで出すことで、モデルが要約した内容を確かめてから保存できた。ツール名だけでは承認の意味が薄い
  - **会話を引き継ぐには**：
    - 今の CLI は1回の質問ごとにプロセスが終わり、`run_sync` に履歴を渡していない。そのため「LoRAとQLoRAの違いは？」のあとに「これを記録して」と聞いても、モデルには「これ」が何か分からない（LLM の API 自体も状態を持たない）
    - 1つのプロセスの中で質問をループし、`history = result.all_messages()` を次の `run_sync(message_history=history)` に渡す対話モードにすれば、会話が引き継がれる。承認の再開で使った `message_history` と同じ仕組み
    - ただし、履歴が長くなるほど毎回送るトークンが増えるので、古い履歴を削る・要約するなどの工夫が要りそう
